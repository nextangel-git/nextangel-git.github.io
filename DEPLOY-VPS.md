# VPS — дополнительный вариант развёртывания

Основное решение проекта — статический хостинг с браузерной админкой (DEPLOY.md). Этот вариант нужен только при отдельном выборе VPS и локальной Express-админки. Конфиги в deploy/ — шаблоны; на реальном сервере в рамках аудита они не запускались.

## Подготовка

Нужны Linux-сервер, Git, nginx, Node.js 24/npm, HTTPS и менеджер процессов PM2 либо systemd. Стоимость и ресурсы выбираются по условиям хостера; старые ценовые ориентиры не используются. Установку ОС и пакетов выполняет администратор. Приложение запускается от отдельного системного пользователя без прав root.

```bash
cd /var/www
git clone https://github.com/nextangel-git/nextangel-git.github.io.git jks
cd jks
npm ci
npm ci --prefix admin
npm test
SITE_URL=https://jks.ooo PUBLIC_FORM_TARGET=uk@jks.ooo npm run build
npm run test:build
cd admin
npm ci --omit=dev
node server.mjs --add-user uk 'Сотрудник УК' '<собственный пароль>'
```

Клонирование не включает соседний migration/. Старых PDF в поставке нет; действующие документы загружаются отдельно через админку. Никакие автоматически удалённые старые файлы восстанавливать или переписывать ссылками без проверки не нужно.

## Секреты и процесс

`admin/users.json`, `admin/.secret` и `.env` не коммитятся и не публикуются. Секрет сессии создаётся приложением либо передаётся через переменную окружения SESSION_SECRET. В конфиге PM2 секрета нет. Ограничьте права файлов учётной записью приложения.

Перед стартом задайте переменные окружения `SITE_URL=https://jks.ooo`, `PUBLIC_FORM_TARGET=uk@jks.ooo`; они нужны также последующим сборкам из админки. Из корня проекта:

```bash
pm2 start deploy/ecosystem.config.cjs
pm2 save
pm2 startup
```

В шаблоне включены HTTPS=1 (secure-cookie за nginx), REBUILD=1 (локальная пересборка), GIT_PUSH=1 (отправка коммитов на GitHub). Учётные данные Git и автора коммитов настройте отдельно для пользователя приложения, не для root. Если публикация на Pages больше не нужна, отдельно согласуйте отключение текущего workflow; иначе push обновит и Pages.

Локальная админка использует логин, пароль и SVG-капчу. 2FA отключена, QR-настройки нет. Сессии находятся в памяти: перезапуск потребует нового входа. Для пользователей не использовать старые тестовые пароли.

## nginx и HTTPS

1. В deploy/nginx-jks.conf проверить домены, корень `/var/www/jks/dist` и адрес админки 127.0.0.1:4777.
2. Подключить конфигурацию и выполнить `nginx -t` до перезагрузки nginx.
3. Настроить DNS на сервер и выпустить сертификат для согласованных доменов. Включить перенаправление HTTP на HTTPS; пока HTTPS не работает, secure-cookie не позволит пользоваться серверной админкой.
4. Убедиться, что node-порт недоступен извне. Публикуется только dist, не `/var/www/jks` целиком.

Шаблон отдаёт отсутствующие страницы с HTTP 404 через `404.html`, кеширует бессрочно только хешированные файлы `/_astro/` и разрешает тело запроса до 26 МБ для файла до 25 МБ. Прокси передаёт X-Forwarded-Proto; приложение доверяет локальному прокси при HTTPS=1.

## Данные и синхронизация

Локальные сохранения меняют файлы и Git; следите за конфликтами, если одновременно используется браузерная GitHub-админка. Рекомендуется выбрать один рабочий способ редактирования либо явно синхронизировать копии перед правками. Скрипты migration и расписание переносите отдельно; синхронизация может менять данные и отправлять коммит.

При переключении старого сайта на новый согласуйте карту редиректов из migration/redirects-map.md и проверьте нужные ссылки. Резервируйте исходники, документы, файлы пользователей и настройки вне публичного каталога.

## Приёмка сервера

- [ ] HTTPS и сертификаты работают на согласованных доменах.
- [ ] Сайт открывает все страницы, отсутствующий адрес возвращает 404.
- [ ] admin.jks.ooo: вход и загрузка файла до разрешённого лимита проверены.
- [ ] После сохранения видны новая сборка и ожидаемый Git-коммит.
- [ ] Параллельная работа не перезаписывает изменения из другой копии.
- [ ] Секреты и исходники не доступны по HTTP.
- [ ] FormSubmit активирован УК, доставка контрольной заявки подтверждена.
- [ ] Автозапуск и восстановление после сбоя проверены на сервере.
