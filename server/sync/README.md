## Установка и расписание

Исходники находятся в Git, но Astro не копирует их в `dist`. На сервере `cron.php`, `core.php`, `vk.php`, `mingkh.php` установлены в `/home/jksooo/jks.ooo/.jks-admin/sync/`; каталог — 0700, файлы — 0600. Рядом находится приватный `settings.json`. GitHub-токен читается из существующего `../config.php`, в настройки и командную строку его не копируют.

В [панели cron NIC.RU](https://www.nic.ru/hcp2/cron/) выбрана PHP-конфигурация сайта `jks.ooo`, файл `/home/jksooo/jks.ooo/.jks-admin/sync/cron.php`, расписание `17 * * * *`. Требуются PHP 8.1+ и расширения curl, DOM, iconv. Node.js, Python, Git и включённый локальный компьютер не нужны. HTTP-запуск этого скрипта запрещён.

VK проверяется каждый час в 17 минут. Mingkh после первого успешного рабочего сбора проверяется 5-го числа каждого месяца в 10:17 по `Asia/Krasnoyarsk`; срок вычисляет PHP. Пропущенный срок или ошибка повторяются ближайшим часовым запуском. Первый сбор и смена режима dry-run/рабочий выполняются без ожидания месячной даты. Общий `flock` исключает одновременные серверные запуски.

## Данные и публикация

VK получает последние 10 записей официального публичного виджета сообщества 189230176 без токена и авторизованной вкладки браузера. На главной отображаются четыре. Проверяются структура ответа, владелец, идентификаторы и даты. Относительная дата без точного значения сохраняется как `null` с предупреждением в отчёте.

Mingkh читает открытые карточки Сосновоборска на dom.mingkh.ru. Проверяются полнота, адреса и числовые диапазоны. Утверждённый список домов ЖКС не изменяется; расхождения управляющих компаний попадают в закрытый отчёт. Известные координаты сохраняются, автоматического геокодинга нет.

При ошибке или неполном ответе источника предыдущие данные сохраняются. Рабочий запуск может атомарно изменить только `src/data/vk_posts.json`, `src/data/houses_geo.json`, `src/data/competitors.json` и журнал в SUMMARY.md. Конфликт GitHub HEAD останавливает запись без force. GitHub Actions выполняет тесты, сборку и доставку на NIC.RU и Pages; статус `committed` означает создание коммита, а успешную публикацию подтверждают отдельно.

## Сопровождение

`vk-status.json`/`mingkh-status.json`, preview и snapshot находятся в приватном каталоге. Рабочий успех записывает `last_success`, dry-run — `last_preview`. Секреты и HTML источников в журнал не выводятся. Вывод cron доступен в панели NIC.RU.

Ключ `--dry-run` запрещает коммиты и сохраняет preview при наличии изменений; `unchanged` может не создавать новый preview. `--only=vk` и `--only=mingkh` выбирают источник. `--force` обходит расписание, но не отменяет dry-run, выключенную задачу или проверки данных. Образец `settings.example.json` намеренно оставлен в безопасном режиме dry-run для новой установки.

Для остановки отключить cron в панели, сохранив состояние. PHP-код обновляется отдельной установкой вне webroot: обычный FTPS-деплой его не переносит.

## Защита от локальных дублей

Создан `../migration/sync-owner.json` с `{"owner":"nic"}`. Старые `mingkh_sync.py` и `vk_extract.py` завершаются с кодом 1 до сетевых запросов. Локальная Express-админка отключает кнопки и возвращает 409 на POST `/sync/mingkh` и `/sync/vk`. Проверки блокировки пройдены. Без маркера или при `owner:local` остаётся прежний локальный режим; не переключайте владельца, пока работает NIC-задача.

История внешних локальных планировщиков отдельно не подтверждена; даже сохранённое старое задание теперь упирается в запрет entrypoint. Подробности старых инструментов — в [DEPLOY.md](../../DEPLOY.md#прежние-локальные-точки-запуска-история-и-предотвращение-дублей).

Для диагностики status содержит стадию, версию PHP, лимит и пик памяти, длительность. При аварийном завершении PHP сохраняется фиксированный код без исходного сообщения; после внешнего уничтожения процесса следующий запуск с полученным lock переводит старый running в interrupted. Повтор сохраняет часовую паузу с допуском для задержек планировщика.
