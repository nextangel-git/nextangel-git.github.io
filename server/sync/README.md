# Обновления из cron NIC.RU

Состояние на этапе настройки: в NIC.RU создан **dry-run cron**. Автоматическая запись в GitHub ещё не подтверждена как включённая; успешный dry-run не считается боевой публикацией. Актуальный результат запуска проверяют по приватным status-файлам и журналу панели.

Исходники находятся в Git, но не копируются Astro в `dist`. Установка: четыре PHP-файла в `/home/jksooo/jks.ooo/.jks-admin/sync/`, каталог0700, файлы0600. Рядом нужен приватный `settings.json` по образцу `settings.example.json`. Токен GitHub читается из существующего `../config.php`; новых ключей и токенов в исходниках нет.

В [панели cron NIC.RU](https://www.nic.ru/hcp2/cron/) выбирается интерпретатор PHP конфигурации сайта `jks.ooo`, файл `/home/jksooo/jks.ooo/.jks-admin/sync/cron.php`, расписание `17 * * * *`. Нужны PHP 8.1+ и расширения curl, DOM, iconv. Внешний HTTP-вызов не поддерживается. Node.js, Python, Git и работающий домашний компьютер не нужны.

Планируемое рабочее расписание: одна задача каждый час в 17 минут. VK проверяется каждый час. Mingkh при первом запуске собирается сразу, затем 5-го числа месяца в 10:17 по `Asia/Krasnoyarsk`; срок вычисляется внутри PHP, а не отдельным месячным заданием NIC. Если хостинг пропустил время, следующий час догонит запуск. После ошибки повтор возможен через час. Общий flock не позволяет двум серверным копиям работать одновременно и освобождается при завершении процесса.

Dry-run записывает `last_preview`, рабочий успех — `last_success`. Пока рабочего успеха нет, mingkh в пробном режиме может выполняться каждый час. Переключение dry-run/рабочий тоже инициирует сбор без ожидания месячного срока. Поэтому прежде чем менять режим, нужно проверить preview и согласовать спорные изменения; наличие пробной задачи не подтверждает активацию рабочего расписания.

VK: официальный публичный виджет сообщества189230176, без токена и авторизованной вкладки браузера. HTML проверяется по структуре и владельцу постов. При недостаточном/ошибочном ответе прежняя лента сохраняется. Относительные даты, которые нельзя надёжно восстановить, не выдаются за абсолютные.

Mingkh: открытые карточки Сосновоборска на dom.mingkh.ru. Проверяются страницы, адреса, числовые диапазоны, полнота полученных карточек. Утверждённый список домов ЖКС не изменяется; расхождения управляющих компаний попадают в закрытый отчёт. Известные координаты сохраняются, автоматического геокодинга нет.

Текущие пробные настройки по образцу: `{"dry_run":true,"vk":true,"mingkh":true}`. При наличии отличий результаты записываются в `vk-preview.json`/`mingkh-preview.json`, GitHub не изменяется. `unchanged` означает успешный сбор без изменений и может не создавать новый preview. Отдельный переход на `dry_run:false` после проверки разрешит атомарные коммиты только `src/data/vk_posts.json`, `src/data/houses_geo.json`, `src/data/competitors.json` и записи в SUMMARY.md. При конфликте main перезапись запрещена; повторный запуск прочитает свежий HEAD. GitHub Actions выполняет тесты, сборку и публикацию на NIC.RU и Pages. Отчёт `committed` означает создание коммита, а не успешную доставку — статус Actions проверяется отдельно. Этот переход пока не подтверждён как выполненный.

Состояние последнего запуска: `vk-status.json`/`mingkh-status.json` в том же приватном каталоге; вывод задач сохраняется панелью NIC. Секреты и HTML источников в журналы не выводятся. Параметры CLI для сопровождения: `--dry-run`, `--force`, `--only=vk`, `--only=mingkh`. `--dry-run` принудительно запрещает коммиты; `--force` только обходит расписание, но не разрешает выключенную в settings задачу и не отключает проверки. Для приостановки отключить cron в панели, сохранив состояние и preview.

При обновлении PHP-кода cron нужно отдельно установить эти файлы вне webroot: обычный статический деплой их не переносит. `settings.json` не публикуется, GitHub-токен не дублируется. Перед рабочей активацией найти и отключить старые задачи, вызывающие `migration/mingkh_sync.py` или `migration/vk_extract.py`, сохранив их экспорт. Локальная Express-админка пока содержит те же вызовы в POST `/sync/mingkh` и `/sync/vk`; ими не пользоваться параллельно NIC. Старые скрипты и кнопки ещё не заблокированы программно. План отказа локальных entrypoints и исторические ограничения описаны в [DEPLOY.md](../../DEPLOY.md#прежние-локальные-точки-запуска-история-и-предотвращение-дублей).
