# Инструкция администратора сайта

Публичный сайт — Astro/JSON на NIC.RU. Новый вход `/admin` использует логин и пароль, серверную PHP-сессию и GitHub API через `/api/admin.php`. Сервер настроен: 19.11.2026 десять реальных API-проверок прошли успешно, включая вход jksadmin, чтение GitHub, CSRF и выход. Доставка нового интерфейса ещё завершается; её подтверждение смотрите в SUMMARY.md.

## Архитектура и доступы

Браузер сотрудника → PHP API на jks.ooo → фиксированный GitHub-репозиторий и ветка main → Actions → публикация на NIC.RU. GitHub PAT хранится на сервере, не передаётся браузеру и не записывается в localStorage. Старый способ первичной привязки браузера с PAT больше не является рабочей схемой нового входа.

Публичные PHP-файлы: api/admin.php, api/admin-core.php, api/admin-schema.php. Приватная конфигурация — `/home/jksooo/jks.ooo/.jks-admin/config.php`, вне `/home/jksooo/jks.ooo/docs`. Она содержит `github_token` и массив пользователей с `password_hash`, `name`, `enabled`. Provisioning выполняется отдельно. Не копировать config в public/, dist/ или репозиторий.

19.11.2026 Денис разрешил использовать на NIC.RU существующий GitHub-токен с правами `repo`, `workflow`, `gist` и выбрал начальный логин `jksadmin`. Конфигурация с хешем пароля размещена в приватном серверном каталоге вне webroot; вход через API подтверждён. Права каталога — 0700, config — 0600. Одноразовый установщик удалил себя, контрольный HTTP-запрос вернул 404. Рекомендуемая последующая замена — отдельный fine-grained PAT с Contents: Read and write только для репозитория сайта; выбранный текущий токен имеет более широкие права. Значения токена и пароля в документацию не включаются.

Для создания нового config используется `admin/provision-php.php` с абсолютным приватным `--output` и JSON из stdin (`--stdin`) либо документированными переменными окружения — см. DEPLOY.md. Реальные пароль и токен не передаются аргументами и не печатаются. Существующий config CLI не перезаписывает и сам ничего не загружает на сервер. Для размещения config нужен отдельный административный доступ выше docs; FTPS-доступ Actions ограничен webroot.

FTPS-секреты GitHub Actions нужны для доставки сборки. PAT в серверном config нужен для записи контента через админку. Эти доступы различаются; отзыв одного не заменяет отзыв другого. При передаче УК обновляются серверная конфигурация, фиксированные OWNER/REPO в PHP-коде и настройки доставки.

## Учётные записи и сессии

Сотрудник получает логин и начальный пароль по согласованному закрытому каналу. Пароли хранятся только как хеши. Смена пароля требует текущего пароля; новый пароль — минимум 10 символов и не более 72 байт UTF-8. Для забытого пароля технический администратор атомарно заменяет хеш в приватном config и проверяет, что прежние сессии больше не действуют. Отключение пользователя — `enabled=false`.

Cookie `__Host-jks_admin`: Secure, HttpOnly, SameSite=Strict, Path=/. Сессия завершается после 30 минут простоя либо 8 часов с момента входа. Logout удаляет авторизацию. Изменяющие операции требуют CSRF-токен и допустимый Origin; сервер ограничивает перебор паролей. 2FA не включена.

GitHub Pages не исполняет PHP: пользоваться новой админкой нужно только на https://jks.ooo/admin. Локальная Express-админка остаётся отдельной опцией с собственными пользователями и сессиями; она не управляет PHP-учётными записями.

## PHP на NIC.RU

На NIC.RU 19.11.2026 подтверждены PHP 8.5.12, UTF-8, curl и `post_max_size=64M`. Общий `memory_limit=64M`; обработчик commit после авторизации и CSRF-проверки поднимает лимит текущего запроса до 256M, сохраняя более высокий или unlimited лимит. Если хостинг запрещает повышение, commit отвечает `503 upload_memory_limit`; вход и чтение остаются доступны. `.user.ini` и общий php.ini не менялись. PHP пишет в приватный `.jks-admin` для конфигурации, сессий и rate-limit. Файл размером до 25 МиБ передаётся в JSON/base64.

Сборка и FTPS-деплой не создают пользователей, не копируют PAT и не трогают приватный соседний каталог. PHP-код может обновиться независимо от config; совместимость при изменении схемы проверяется до публикации. Проверяйте, что хостинг исполняет PHP и не отдаёт его исходники.

## Контент и публикация

Сохранение создаёт Git-коммит; сайт изменится после успешного Actions и NIC-деплоя. При конфликте перечитать актуальные данные и перенести правку, не перезаписывая чужое изменение. Если gate `NIC_DEPLOY_ENABLED` выключен или FTPS-job завершилась ошибкой, коммит ещё не означает обновление сайта. Статус включения доставки указан в SUMMARY.md.

Форма обращений отправляет через FormSubmit на uk@jks.ooo. Активацию и получение подтверждает сотрудник с доступом к почте. requests.json и личный кабинет не являются автоматически связанным журналом этих обращений.

## Синхронизация

Скрипты mingkh/VK находятся в соседнем migration/, вне репозитория сайта. Запуск выполняется отдельно или через локальную Express-админку; новый PHP API не запускает shell/Python. Существование ежемесячного расписания проверяется отдельно. Синк может менять данные и делать commit/push.

## Бэкапы и восстановление

Код, JSON и загруженные через админку документы — история Git. Откат — проверенный revert и повторная публикация. Приватная PHP-конфигурация с PAT, пользователи, сессии, автоматизации и файлы вне Git требуют отдельного защищённого резервирования. Не публиковать архив конфигурации или содержимое .jks-admin по HTTP.

## Типовые проблемы

| Симптом | Действие |
|---|---|
| API 503 | Проверить приватный config, права, PHP/curl; не выводить токен в логи |
| Вход отклонён | Проверить логин, пароль, enabled; учесть блокировку перебора |
| Сессия истекла | Повторить вход; убедиться в HTTPS и разрешённых cookie |
| Изменение не сохранилось | Проверить сообщение о конфликте, CSRF и права серверного PAT |
| Коммит есть, сайт старый | Проверить сборку и job deploy-nic, gate и FTPS-доступ |
| Загрузка отклонена по размеру | Проверить лимит 25 МиБ и настройки post_max_size/memory_limit |
| Письмо с заявкой не пришло | Проверить FormSubmit, адрес, спам; использовать резервное письмо/телефон |

Сопровождение: Денис. В сообщениях об ошибках не передавать пароли, cookie, PAT и config.php.
