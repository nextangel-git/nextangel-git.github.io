# Инструкция администратора сайта

Сайт — статическая сборка Astro; источник данных — JSON в Git. Основная админка `/admin` сохраняет через GitHub API, после чего Actions публикует GitHub Pages. Локальная Express-админка — дополнительная опция. Процессы запуска и переноса описаны в DEPLOY.md, передача УК — в HANDOVER.md.

## Доступ

Первичная настройка браузера: fine-grained PAT только на репозиторий сайта, Contents: Read and write, затем пароль сотрудника. PAT хранится в localStorage в зашифрованном виде. Последующие входы — пароль и Яндекс SmartCaptcha. Капча проверяется только клиентски; права записи определяет GitHub. 2FA отключена по решению владельца.

У каждого сотрудника может быть свой PAT, чтобы отзывать его отдельно. Смена пароля в админке меняет шифрование локальной привязки, не пароль GitHub. Если пароль забыт, сбросить привязку и заново настроить её с действующим PAT. При смене браузера/домена нужна новая привязка.

Локальная Express-админка использует отдельные логин/пароль и SVG-капчу. Её users.json и .secret не публикуются. Сессии находятся в памяти процесса: перезапуск требует нового входа.

## Контент и публикация

Сохранение в основной админке создаёт коммит; результат виден после успешной сборки Actions. При конфликте параллельных изменений перечитать актуальные данные и повторить правку. Не перезаписывать чужие изменения вслепую.

На стороннем статическом хостинге потребуется отдельная доставка dist/: текущий workflow публикует только GitHub Pages. Обновление JSON на GitHub само по себе не обновляет произвольный shared-хостинг.

Форма отправляет через FormSubmit на uk@jks.ooo. Активацию адреса и доставку подтверждает сотрудник с доступом к почте. Заявки не поступают в requests.json и не синхронизируются с личным кабинетом; раздел админки не является журналом обращений.

## Синхронизация

Скрипты mingkh/VK лежат в соседнем каталоге migration, вне репозитория сайта. Ручной запуск доступен в локальной Express-админке при наличии этих скриптов и окружения. В статической админке кнопок запуска нет. Эти операции изменяют данные; mingkh может сделать commit/push.

Ежемесячное расписание — отдельная автоматизация на машине, а не GitHub Actions. Перед передачей УК проверить, где оно настроено, кто его обслуживает и как проверяется результат. При менее чем 100 собранных карточках mingkh выводит сообщение и прерывает обновление; это не заменяет контроль полноты данных.

## Резервные копии и восстановление

Код и опубликованные данные — история Git. Откат — проверенный revert нужного коммита, затем успешная пересборка. Документы, загруженные через статическую админку, лежат в public/documents и входят в Git. Локальные файлы вне Git, настройки автоматизаций и доступы требуют отдельного резервирования. Корень репозитория и admin/ никогда не публикуются как каталог сайта.

## Типовые проблемы

| Симптом | Действие |
|---|---|
| PAT отклонён или нет права записи | Проверить срок и права токена; сбросить привязку при замене |
| Правка не появилась | Проверить статус и журнал Actions, затем кеш браузера |
| Капча не загрузилась | Проверить доступ к smartcaptcha.yandexcloud.net и блокировщик |
| Конфликт сохранения | Загрузить свежую версию, перенести свою правку и сохранить повторно |
| Нет заявки в почте | Проверить активацию FormSubmit, адрес получателя и спам; воспользоваться резервным письмом или телефоном |
| Сайт недоступен | Проверить GitHub Status, Pages, DNS и сертификат |

Сопровождение: Денис. Не пересылайте PAT, пароли или содержимое users.json в сообщения об ошибках.
